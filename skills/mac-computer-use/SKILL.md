# Управление Mac: сначала командная строка, GUI — последним

## Лестница (правило владельца)

Выбирай самую нижнюю ступень, которой хватает. GUI — только когда первые две
не справляются.

1. **Командная строка** через `bb terminal run --machine <mac> -- bash -lc '…'`:
   `open -a TextEdit file.txt`, `open "https://…"`, `defaults read/write`,
   `mdfind`, `ls`/`cp`/`mv`, `pmset`, `networksetup`, `osascript -e '…'`,
   CLI самих приложений (`code`, `/Applications/…/Contents/MacOS/…`).
2. **Скриптовые и программные интерфейсы**: AppleScript/JXA по словарю
   приложения (`osascript -e 'tell application "Notes" to make new note …'`;
   словарь — `sdef /Applications/Notes.app | head`), `shortcuts list` и
   `shortcuts run "<имя>"`, URL-схемы, HTTP/API приложений; действия
   Accessibility по элементам без мыши — `mac_action` с `element_token`,
   `set_value`, `invoke_menu`, `type_text` по токену.
3. **GUI** — экран, мышь, клавиатура (`mac_screenshot`, клики по `x,y`,
   `move_cursor`, `drag`, `delivery_mode: "foreground"`): только если у
   приложения нет CLI/AppleScript/API или нужно увидеть, что на экране.

Перед первым GUI-шагом в задаче коротко напиши пользователю, почему не хватило
ступеней 1–2 («у приложения нет AppleScript-команды для этой кнопки»). Тот же
смысл передавай в обязательном параметре `why_gui` инструментов `mac_screenshot`
и `mac_action`: он виден пользователю в журнале GUI-действий в настройках плагина.

Особенности: `screencapture` из службы BB даёт чёрный экран — смотреть экран
только через `mac_screenshot`. AppleScript к приложению при первом обращении
может вызвать системный запрос «Автоматизация» — тогда остановись и попроси
пользователя разрешить на Mac.

## Инструменты GUI-уровня

Плагин `mac-computer-use` даёт агентам три инструмента. Все работают с явно
указанным Mac (`machine` — ID `host_…` или точное имя из `bb machine list`).
Команды исполняет служба BB на самом Mac через Cua Driver
(`/Applications/CuaDriver.app`), поэтому вызывать можно из треда на любой машине.

| Инструмент | Зачем |
| --- | --- |
| `mac_screenshot {machine, why_gui}` | Снимок всего экрана (картинка). |
| `mac_screenshot {machine, pid, window_id, why_gui}` | Окно: дерево элементов `[N] AXRole "имя"` + `snapshot_id` + картинка. |
| `mac_action {machine, tool, args, why_gui, step?}` | Любой инструмент Cua Driver: `list_apps`, `list_windows`, `launch_app`, `click`, `type_text`, `press_key`, `hotkey`, `scroll`, `move_cursor`, `set_value`, `invoke_menu`, `run_steps`… |
| `mac_tool_info {machine, tool?}` | Короткий список инструментов; аргументы инструмента (`tool: "click"`); `tool: "status"` — служба, разрешения macOS и выданный доступ. |

GUI-доступ к каждому Mac выдаёт пользователь в настройках плагина
(Settings → Mac Computer Use → «Компьютеры и доступ»): включён ли компьютер,
можно ли видеть экран, выполнять действия в приложениях, отдельно — мышь по
координатам, список разрешённых приложений. Командный доступ (`bb terminal`)
этой настройкой не управляется. Отказ «доступ выключен» или «приложение не разрешено» — не обходи,
сообщи пользователю.

## Видимый режим

Пользователь видит, что делает агент: на Mac подсвечивается курсор агента
(синее кольцо, свечение) и появляется подпись «BB · <проект>: <шаг>»; через
несколько секунд без действий она гаснет. Фокус и курсор пользователя не
перехватываются. Передавай в `mac_action`/`mac_screenshot` короткий `step`
(2–6 слов, для человека): «печатает ответ в TextEdit», «нажимает Отправить».
Без `step` подпись строится по инструменту и приложению. Показ и вывод окна на
передний план настраивает пользователь (по умолчанию: показ включён, фоновый
режим без активации окна).

## Рабочий цикл GUI (ступени 2–3)

1. `mac_action {tool: "list_windows", args: {"app": "TextEdit"}}` → `pid`, `window_id`.
   Всегда фильтруй (`app` или `pid`): без фильтра список окон огромный.
   Заголовок может отличаться («Untitled.rtf»), окно может быть на другом Space
   (`is_on_screen: false`) — снимок и ввод всё равно работают.
   Нет приложения — `launch_app {"bundle_id": "com.apple.TextEdit"}` (запуск в
   фоне, фокус пользователя не перехватывается).
2. `mac_screenshot {pid, window_id}` → дерево и `snapshot_id`.
   **element_token = `<snapshot_id>:<N>`**, где N — номер в квадратных скобках:
   строка `[1] AXTextArea` в снимке `s00000006` → `"s00000006:1"`.
3. Действие:
   - кнопки, пункты, флажки: `click {"pid", "window_id", "element_token"}`;
   - текстовые поля: `type_text {"pid", "window_id", "element_token", "text"}`
     или `set_value` (click по токену текстовой области даёт AXPress -25206 — это норма);
   - холсты, видео, нестандартные элементы: `click {"pid", "window_id", "x", "y"}`,
     x,y — пиксели картинки окна из последнего `mac_screenshot`;
   - клавиши в фоновом приложении: `hotkey {"pid", "keys": ["cmd","n"]}`
     (драйвер сам выберет пункт меню), `invoke_menu` для меню;
   - `move_cursor {"x","y"}` — экранные координаты, нужен редко.
4. Снова `mac_screenshot` окна — проверить результат: `click` и `move_cursor`
   почти всегда отвечают `effect: "unverifiable"`, это не ошибка. `type_text`
   подтверждает себя сам (`value_readback`) и может добавить «пробел+backspace»,
   чтобы документ заметил правку. Токены устаревают после каждого нового снимка
   окна — бери их из самого свежего.
5. Несколько шагов одним вызовом — `run_steps`: шаги можно адресовать по имени
   без токенов, например
   `{"steps":[{"click":{"app":"TextEdit","role":"button","name":"New Document"}},{"type_text":{"role":"textarea","text":"…"}}],"observe":true}`.
   Справка: `mac_action {tool: "get_guide", args: {"topic": "batching"}}`.

Плагин сам ведёт сессию драйвера для каждого треда (`session` подставлять не
нужно): снимок и его токены доступны следующим вызовам того же треда.
У агента свой курсор: по умолчанию всё делается в фоне и не мешает пользователю.
`delivery_mode: "foreground"` — только если фоновый способ не сработал.

## Границы

- Отправка сообщений, публикация, покупки и оплата, удаление файлов/данных,
  изменение настроек безопасности — только после явного подтверждения
  пользователя на этот конкретный шаг.
- Не вводи пароли и секреты и не пересказывай их с экрана. Окно пароля, 2FA или
  системный запрос разрешения — остановись и попроси пользователя.
- Снимки экрана содержат личные данные: не сохраняй и не пересылай их без
  необходимости задачи. Не трогай чужие окна и документы, не относящиеся к задаче.
- Плагин запрещает `kill_app`, `clipboard_read`, `set_config` и некоторые другие
  инструменты (настройка `deniedTools`). Не обходи запреты через терминал.
- Сайты — через browser-automation; файлы и команды — через `bb terminal run`.

## Ошибки

- `Cua Driver не установлен` / `разрешения не выданы` / `permissions_pending`:
  попроси пользователя открыть Settings → Mac Computer Use и нажать
  «Установить» или «Открыть мастер разрешений», затем включить CuaDriver в
  «Универсальный доступ» и «Запись экрана и системного звука». Сам переключатели
  не меняй.
- `stale_element_token` / `window_never_read`: сделай свежий `mac_screenshot`
  этого окна и повтори с новым токеном.
- Служба Cua Driver запускается автоматически при вызове.

Без инструментов `mac_*` (старая сессия агента): `bb terminal run --machine <mac> --
~/.local/bin/cua-driver call <tool> '<json с "session":"<имя>">'`; снимок —
`--screenshot-out-file /tmp/x.png`.
