# Mac Computer Use — плагин BB

[English version](README.md)

Агенты BB в любом треде и на любой подключённой машине видят экран Mac и управляют им как человек: снимки экрана, клики, ввод текста, сочетания клавиш, прокрутка, запуск приложений. Основан на открытом [Cua Driver](https://github.com/trycua/cua) (MIT).

## Сначала командная строка, GUI — последним

Агенты идут по лестнице и выбирают самую нижнюю ступень, которой хватает:

1. **Командная строка без управления другими приложениями** через `bb terminal run --machine <mac>`: shell, `open`, `defaults`, `mdfind`, CLI приложений, файлы документов.
2. **Действия Accessibility без мыши** через Cua Driver (`element_token`, `set_value`, `invoke_menu`) — без новых системных запросов.
3. **AppleScript** только через `mac_applescript` и помощника «BB Automation»: macOS спрашивает «"BB Automation" хочет управлять "<приложение>"», а не называет службу BB («node»).
4. **GUI** — экран, мышь и клавиатура — только если ступени 1–3 не справляются.

Агентам запрещено запускать `osascript` к другим приложениям из `bb terminal`: macOS тогда показывает «"node" хочет управлять …» отдельно для каждого приложения.

GUI-инструменты требуют аргумент `why_gui`: агент объясняет, почему не хватило командной строки и скриптов. На экране настроек ведётся журнал GUI-действий с этими причинами. Плагин управляет только GUI-доступом; командный доступ через `bb terminal` регулирует сам BB.

## Видимый режим

Пока агент работает, это видно на Mac: подсвечен курсор агента (свечение, круги при клике), рядом синяя плашка в две строки — «BB · <проект> — Цель: <цель>» и «Сейчас: <шаг>», через несколько секунд она гаснет. Плашка — окно-оверлей поверх всех окон, не забирающее фокус. Агенты передают `goal` один раз на тред (по умолчанию — название треда) и короткий `step` на действие (по умолчанию — по инструменту и приложению).

На плашке есть кнопка **«Остановить агента»**: одно нажатие сразу отзывает GUI-доступ для сеанса этого треда; дальнейшие GUI-вызовы отклоняются, пока пользователь не нажмёт «Разрешить снова» в настройках (или не пройдёт 12 часов). Глобальная горячая клавиша не регистрируется: для неё нужно ещё одно разрешение macOS («Мониторинг ввода»); кнопки и переключателя компьютера достаточно. Для каждого компьютера: «Показывать действия агента» (по умолчанию вкл) и «Выводить окно на передний план» (по умолчанию выкл — основной режим фоновый).

## Инструменты агентов

| Инструмент | Назначение |
| --- | --- |
| `mac_screenshot {machine, pid?, window_id?, why_gui, step?, goal?}` | Снимок всего экрана или одного окна с деревом элементов и `snapshot_id`. |
| `mac_action {machine, tool, args, why_gui, step?, goal?}` | Любой инструмент Cua Driver: `list_windows`, `launch_app`, `click`, `type_text`, `hotkey`, `scroll`, `run_steps`… |
| `mac_applescript {machine, script, why, timeout_s?}` | AppleScript через помощника «BB Automation» (ступень 3). |
| `mac_tool_info {machine, tool?}` | Список инструментов, аргументы инструмента или `status` (драйвер, разрешения macOS, выданный доступ). |

`machine` — ID машины BB (`host_…`) или её точное имя. Навык `mac-computer-use` учит агентов циклу «посмотреть → сделать → проверить» и правилам безопасности (отправка, покупка, удаление и публикация — только с подтверждения пользователя; пароли не вводить).

## Настройки → Mac Computer Use → «Компьютеры и доступ»

- Выдать или забрать GUI-доступ для каждого компьютера; отдельно — просмотр экрана, действия в приложениях (Accessibility) и мышь по координатам; при желании ограничить списком приложений (bundle id или имя).
- Пошаговый мастер подключения нового Mac; журнал последних GUI-действий с причиной от агента.
- Установить или обновить Cua Driver на Mac: архив релиза проверяется по `SHA256SUMS`, `codesign --verify --deep --strict`, команде разработчика `YCK386LBJ7` (Cua AI, Inc.) и Gatekeeper. Телеметрия выключается.
- Состояние разрешений macOS и кнопка, открывающая мастер разрешений на Mac.
- Проверка связи со снимком экрана.

Компьютер, которого нет в политике доступа, закрыт. По умолчанию запрещены `kill_app`, `clipboard_read`, `set_config`, `install_extension`, `check_for_update`, `replay_trajectory`, `browser_download`, `browser_set_input_files` (`deniedTools`).

## Доступ переживает переустановку BB

Каждая запись доступа хранит, кроме ID машины в BB, устойчивые признаки: имя машины в BB и солёный SHA-256 аппаратного UUID Mac (сам UUID не покидает Mac). Если BB восстановлен с новыми ID машин, старая запись переносится на свой Mac автоматически только когда ровно у одного текущего Mac совпадает аппаратный хэш. Совпадение только по имени или любая неоднозначность доступа не дают: в настройках появляется кнопка «Привязать к этому компьютеру» — решение одним нажатием. Каждая перепривязка и привязка записывается в журнал действий.

## Установка

```sh
bb plugin install git:https://github.com/ainurminibaev/bb-plugin-mac-computer-use.git@^0.3.5
```

Затем Settings → Mac Computer Use: установить Cua Driver на Mac, на самом Mac включить два разрешения («Системные настройки → Конфиденциальность и безопасность → Универсальный доступ» и «Запись экрана и системного звука» → CuaDriver), включить доступ и нажать «Проверить связь». Инструменты появляются в новых сессиях агентов.

Из локальной копии: `npm ci && bb plugin build . && bb plugin install path:$PWD --yes`.

## Обновления и релизы

Установленные с диапазоном версий получают обновления командой `bb plugin update mac-computer-use`.

Выпуск версии:

1. Поднять `version` в `package.json`, добавить раздел в `CHANGELOG.md`.
2. `npm ci && npm run typecheck && npm test && bb plugin build .`
3. Коммит, тег `vX.Y.Z`, push тега, GitHub Release с текстом из CHANGELOG.
4. Опубликованный тег не переносить; исправление — новой версией.

## Требования

- macOS 14+ на управляемом Mac (Apple silicon или Intel), подключённом к BB.
- BB ≥ 0.49, Plugin SDK ≥ 0.6.132.
